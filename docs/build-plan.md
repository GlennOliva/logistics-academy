# Three-Day Build Plan

## Delivery Strategy

Build secure vertical flows before decorative polish. Database and server authorization are authoritative; route guards are navigation aids only. Missing content and commercial inputs remain explicit launch blockers, not mock success paths.

| Day | Budget | Work | Exit evidence |
| --- | --- | --- | --- |
| 1 | 1h review/setup; 2.5h data/RLS/auth; 2h public site; 2h checkout/proof; 0.5h verification | Source records, Vite app, migrations/storage, auth, public pages, authoritative order, validated private proof, payment status, admin inspection | Local quality gates pass; test-project persistence/security checks run when credentials exist |
| 2 | 2h approvals; 2h admin/content; 2h learning; 1h quizzes; 1h integration | Transactional payment decisions/grants, module publishing/versioning, entitled downloads, progress snapshots, authoring and trusted scoring | Approval idempotency and cross-user isolation verified against Supabase test project |
| 3 | 1.5h certificates; 1h refund/report/email; 2.5h security/E2E; 1h responsive QA; 2h release/handover | PDF certificate/verification, reconciliation, safe CSV, outbox worker, security and journey tests, deployment/handover documentation | Test evidence complete or marked NOT RUN; technical and commercial status reported separately |

## Assumptions

- A three-day release candidate depends on timely owner inputs and access to an isolated Supabase project.
- The specification is usable for confirmed facts, but absent local references cannot be represented as independently reviewed.
- Real migrations, publication, emails, and money transfers require separate owner authorization.
- Decorative detail and broad report options are reduced before security or correctness.

## Release Gates

Technical readiness requires ordered migrations, private storage, RLS/direct API tests, typecheck, lint, tests, production build, critical responsive E2E, no bundled secrets, and verified deployment configuration.

Commercial launch readiness additionally requires genuine payment details, all advertised content/translations, approved quiz/certificate/policies, working email, provisioned admin, domain/hosting, owner UAT, and explicit launch authorization.
